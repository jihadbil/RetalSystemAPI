# إصلاح طبقة الوصول للبيانات — 2026-10-16

عولجت النتائج التسع الواردة في [التحليل](data-access-audit-2026-10-16.md)، مع الحفاظ على التعديلات المحلية السابقة. أضيفت 20 حالة اختبار انحدار، منها 6 اختبارات SQL Server فعلية.

## التغييرات

- توحيد التحديث والحذف في `EntityPersistence` عبر المستودعات العامة والمتخصصة. تستخدم النسخة المنفصلة `RowVersion` الخاصة بها للتحقق من التزامن حتى إذا وجدت نسخة أخرى متتبعة. لا تُنسخ مفاتيح الملكية أو حقول الإنشاء أو الحقول المولدة عند التحديث. الحقول ذات القيم الافتراضية عند الإدراج، مثل رصيد الخزينة وكمية المخزون، تظل قابلة للتعديل.
- قراءة المعرف تتحقق من حالة النسخة المحلية وملكيتها قبل إعادتها، وتستخدم استعلامًا مفلترًا عند عدم وجود نسخة محلية. يشمل ذلك هواتف العملاء والموردين وكيانات المنتجات والمحاسبة.
- الحفاظ على `Added` للكيانات الجديدة عند التحديث أو الحذف المنطقي قبل أول حفظ.
- التراجع الصريح أو فشل اعتماد المعاملة يلغي التتبع ويمنع الحفظ وبدء معاملات جديدة باستخدام السياق نفسه. يلزم نطاق/سياق جديد للكتابة بعد ذلك. يعمل تنظيف المعاملة حتى عند إلغاء رمز الطلب، ولا يعاد تشغيل تغييرات العملية الملغاة.
- توحيد مالك تقطيع الصفحات: معاملات دوال `GetPaged...` تحدد الصفحة، بينما تستخدم دوال القراءة بالمواصفة تقطيع المواصفة. العد يتجاهل التقطيع، والترتيب ثابت مع المعرف كفاصل بين القيم المتساوية. أضيف ترتيب ثابت كذلك لصفحات المحاسبة.
- حذف المنتج يشمل أرصدة المستودع الصفرية المرتبطة بباركوداته، بالإضافة إلى أرصدة الصالة وبقية الأبناء.
- فهارس أسماء تصنيفات المصروفات والخزائن فريدة للسجلات الفعالة فقط، بما يطابق فحص التكرار والحذف المنطقي.
- مصنع أدوات EF يقرأ ملفات البيئة المناسبة وأسرار التطوير ومتغيرات البيئة ومعاملات الأوامر. يرفض غياب الاتصال بدل اختيار قاعدة افتراضية. أزيل تجاهل اختلاف النموذج عن الترحيلات، وأصبحت إخفاقات تهيئة الأدوار والصلاحيات تُظهر خطأ واضحًا.

## الترحيل

الملف: `RetalSystemAPI.DataAccess/Migrations/20261016121121_FixDataAccessConsistency.cs`، مع Designer وsnapshot محدثين.

ينشئ فهارس الأسماء المفلترة، ويصلح أرصدة المستودع **الصفرية فقط** التي بقيت فعالة رغم حذف المنتج أو باركوده منطقيًا. لا يخفي أرصدة غير صفرية؛ فهي تحتاج تسوية فعلية. لا يعيد التراجع عن الترحيل إحياء السجلات التي أُصلحت. ويرفض التراجع قبل تغيير المخطط إذا كانت الأسماء المعاد استخدامها لا تناسب الفهارس القديمة.

جُرّب الترحيل على قواعد اختبار مؤقتة. **لم يُطبّق على قاعدة التطبيق أو الإنتاج.** عند النشر يلزم تطبيق الترحيلات بإعداد اتصال صريح، وفق إجراءات المشروع:

```powershell
dotnet ef database update --project RetalSystemAPI.DataAccess --startup-project RetalSystemAPI
```

يمكن توفير الاتصال عبر `ConnectionStrings__DefaultConnection`، أو أسرار التطوير عند اختيار بيئة `Development`. لا تُدرج بيانات الاتصال الحساسة في ملفات المصدر.
