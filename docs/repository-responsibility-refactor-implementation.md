# تنفيذ توزيع مسؤوليات المستودعات

التاريخ: 2026-10-16. اكتمل تنفيذ [الخطة](repository-responsibility-refactor-plan.md).

## العقد الأساسي

اقتصر `IRepository<T>` على سبع عمليات: `GetByIdAsync`، `GetByIdForUpdateAsync`، `ExistsByIdAsync`، `AddAsync`، `AddRangeAsync`، `Update`، `SoftDelete`.

أصبح `Repository<T>` أساسًا مجردًا، وأزيل تسجيل `IRepository<>` المفتوح. تعيد القراءة العادية بيانات دون تتبع، وتحمّل قراءة `ForUpdate` نسخة متتبعة. ما زال `EntityPersistence` يحمي عمليات التعديل والحذف والتزامن، وما زال `UnitOfWork` يمتلك الحفظ والمعاملات والتراجع. بقيت فلاتر المستأجر والحذف المنطقي والتدقيق مشتركة.

## ملكية الاستعلامات

امتلكت المستودعات المتخصصة السبعة عشر الاستعلامات الفعلية لمجالاتها. توجد العقود والتنفيذ الإضافي في ملفات `*.Queries.cs` بجانب المستودع الأصلي؛ الاستعلامات المحاسبية موجودة داخل `AccountingRepository`.

| المجال | المستودعات | المسؤوليات المنقولة |
|---|---|---|
| الكتالوج | Product، Category، Unit | البحث والتفاصيل والتكرار والارتباطات والوحدات والباركودات والصور والاستيراد والتصدير |
| المؤسسة والأطراف | Branch، Tenant، Warehouse، Customer، Supplier | البحث والصفحات والتفاصيل وقوائم الاختيار وفحوص الارتباط والتكرار |
| المشتريات | PurchaseOrder، PurchaseInvoice، PurchaseReturn | الفلاتر والتفاصيل والتحميل للتعديل وفحوص ارتباط المستندات والبنود وإسقاط فاتورة الشراء |
| المبيعات | SalesInvoice، SalesReturn | البحث والتفاصيل والتحميل للتعديل وفحوص الفواتير والبنود والمرتجعات |
| المخزون | Stock، StockTransfer، StockAdjustment | القوائم والصفحات والتنبيهات وأرصدة العمليات والتفاصيل وفحوص الارتباط |
| الحسابات | Accounting | بحث الخزائن والحركات وفئات المصروفات والمصروفات عبر فلاتر محددة |

الواجهات المتخصصة لا تستقبل `Expression` أو `ISpecification`، ولا تعيد `IQueryable`، ولا تعرض إسقاطات عامة. بقيت قواعد الاعتماد والإلغاء والكميات والحسابات داخل الخدمات. بقيت استجابات API وعقود الخدمات كما هي.

نقلت مواصفات المجال إلى `DataAccess/Specifications` وجُعلت داخلية. تحمل الفلاتر في `DataAccess/Queries` قيم البحث فقط، وتحمل أنواع `DataAccess/QueryResults` نتائج الإسقاط دون اعتماد على DTOs الخدمات. لا تبني الخدمات المرحّلة مواصفات بيانات.

تطبق الصفحات داخل المستودع، مع إجمالي قبل التقطيع وترتيب ثابت بمعرّف كفاصل تعادل. لم تعد المواصفات تطبق صفحات، ويشترك البحث في مساعد داخلي محدود. تجمع صفحات المخزون الإجمالي والعناصر في نتيجة واحدة بدل واجهتي العد والقائمة المنفصلتين.

## الاستيراد

يجمع `ProductExcelService` مفاتيح الملف ثم يطلب السجلات المطابقة فقط للتعديل، بما فيها مطابقة المنتج بباركود موجود عند تغيير الاسم. تحمل الاستعلامات المفاتيح والأرصدة على دفعات من 500، وتقيّد الأرصدة بالمخزن المطلوب. تبقى قراءة قيم الباركود العامة دون تتبع ضرورية لمنع التكرار وتوليد الأرقام التالية؛ لا تحمل جميع كيانات المنتجات للتعديل.

تم التحقق على SQL Server من أن 1005 أسماء تتطلب ثلاثة استعلامات تحميل فقط، دون تتبع منتج غير مطلوب. تغطي الاختبارات صيغة الورقة الواحدة والصيغة متعددة الأوراق، وربط رمز المنتج الجديد بباركوده، ثم إعادة تحميل البيانات وتصديرها.

## التحقق

نجح بناء المشاريع التابعة لـ API واجتازت المجموعة **60 اختبارًا، منها 13 على SQL Server، دون فشل أو تخطٍّ**. أضيفت تسعة اختبارات إلى خط الأساس البالغ 51: خمسة للعقود وحقن الاعتمادات والتتبع والدفعات، وأربعة لترجمة الاستعلامات والاستيراد الفعلي على SQL Server.

تغطي المجموعة القائمة كذلك عزل المستأجر والحذف المنطقي والتزامن والتراجع وسلامة النموذج. تحقق اختبار SQL من استعلامات البحث للمستودعات المتخصصة السبعة عشر وتحميل العلاقات والإسقاطات. لم يتطلب هذا التنظيم Migration جديدًا أو تعديل نموذج EF؛ ملفات ترحيل الإصلاحات السابقة مستقلة عنه.

```powershell
$env:RETAL_TEST_SQLSERVER = 'Server=localhost;Integrated Security=True;TrustServerCertificate=True;Connect Timeout=5'
dotnet test tests\RetalSystemAPI.SecurityTests\RetalSystemAPI.SecurityTests.csproj --no-restore --logger 'console;verbosity=minimal'
```

يحصر [سجل ترحيل الاستدعاءات](repository-call-migration.json) الاستدعاءات الـ290 التي جرى جردها عند بدء التنفيذ، مع اسم الدالة النهائية واسم دالة الخدمة. أرقام الأسطر فيه تعود إلى الجرد الأصلي، وقد تشترك عدة استدعاءات قديمة في بديل واحد. يشمل التنفيذ أيضًا الفصل الصريح بين قراءات المعرّف العادية وقراءات التعديل وتحديث البحث المحاسبي.

## حدود التنفيذ

وفق الخطة، يبقى فصل الخدمات الست التي تستخدم `AppDbContext` مباشرة عملًا مستقلًا: `AuthService` و`UserService` و`PosCashService` و`DashboardService` و`FinancialReconciliationService` والاستخدامات الإدارية المباشرة في `TenantService`. نُقلت استدعاءات مستودعاتها المتأثرة بالعقد الجديد، دون توسيع هذه الخطوة إلى إعادة تصميم الهوية والتقارير ونقاط البيع.
